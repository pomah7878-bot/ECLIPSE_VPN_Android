# Публикация Android-релизов

Этот документ задаёт единый формат публичных релизов ECLIPSE Unlimited. Публичная история изменений находится в [CHANGELOG.md](../CHANGELOG.md).

## Правила публикации

- Публиковать только APK актуального нативного приложения с пакетом `com.eclipseunlimited.app`.
- Использовать подпись официального приложения. Проверить установку поверх предыдущей версии до загрузки релиза.
- `versionCode` новой сборки должен быть строго больше предыдущего.
- Тег и версия в названии должны совпадать с `versionName` внутри APK.
- Не прикладывать APK прежнего клиента 1.x к релизам линейки 2.x.
- Не помещать в описание ссылки подписок, UUID, ключи, пароли, токены и персональные данные.
- Автоматически созданные GitHub архивы Source code не являются исходным кодом нативного приложения 2.x; не представлять их как таковые.

## Именование

**Тег:** `2.7.1`  
**Название:** `ECLIPSE Unlimited 2.7.1 для Android`  
**APK:** `EclipseVPN_2.7.1_universal.apk`

Для следующей версии заменить номер во всех трёх местах. Universal APK должен содержать поддерживаемые ABI `arm64-v8a` и `armeabi-v7a`.

## Шаблон описания релиза

```markdown
ECLIPSE Unlimited X.Y.Z — актуальная версия нативного Android-клиента.

**Требования:** Android 8.0 или новее.
**Пакет:** `com.eclipseunlimited.app`.

### Что нового

- Главное пользовательское изменение.
- Второе изменение, если оно есть.

### Исправления

- Понятное описание исправленной проблемы.

### Проверено

- Unit-тесты и release-сборка.
- Установка поверх предыдущей официальной версии.
- Вход, подписка и VPN на реальном устройстве.
- Для заявленной поддержки REALITY: успешный HTTPS-тест фактического outbound с `security=reality`.

### Установка

Скачайте APK ниже и установите его поверх предыдущей версии, не удаляя приложение. При первой установке Android может запросить разрешение на установку из выбранного источника.

**SHA-256:**
`<контрольная сумма APK>`
```

Если раздел не содержит изменений, его можно убрать. Не использовать общие фразы вроде «улучшена стабильность», если неизвестно, что именно изменилось.

## Проверка перед публикацией

1. Выполнить unit-тесты и собрать подписанный `siteRelease`.
2. Установить APK поверх предыдущей официальной версии.
3. Проверить пакет, `versionName`, `versionCode` и ABI.
4. Проверить вход, загрузку подписки, подключение и доступ в интернет.
5. Отдельно подтвердить REALITY по фактическому outbound, а не по значку VPN или успешному TLS.
6. Вычислить SHA-256 именно того файла, который будет загружен в релиз.
7. Опубликовать тот же APK на официальной странице и сверить публичные метаданные.

## После публикации

- Открыть страницу релиза без авторизации и проверить название, описание и доступность APK.
- Скачать опубликованный файл и повторно сверить SHA-256.
- Проверить, что официальный сайт предлагает ту же версию.
- Убедиться, что ссылка «Latest release» не ведёт на более старую или другую линейку приложения.
- Обновить [README.md](../README.md) и [CHANGELOG.md](../CHANGELOG.md), если изменилась актуальная версия.

Старые подписанные релизы не удалять ради оформления. Ошибочную публикацию сначала пометить и разобрать отдельно: удаление меняет доступные пользователям файлы и историю загрузок.
